## Key Decisions

- **Unit system**: FLB edges stay in decimal (0.03 = 3pp); Kelly edge is EV-per-dollar; fees are in pp. Conversion: FLB subtracts `feePP / 100`, Kelly subtracts `effectiveFeeRate` directly.
- **Theta break-even computed in processMarket**, not ThetaEngine — keeps ThetaEngine fee-unaware since it doesn't know about spread/fees.
- **ExecutionContext in main.jsx**, not App.jsx — hooks can't consume context from providers in the same component's return.
- **No `Math.max(0, score)` in calculateEdgeScore** — negative scores are valid (DEAD_MONEY, LOW_LIQUIDITY penalties).
- **`_executionStyle` underscore convention** in filters object — acknowledged as tech debt (#5) but skipped for now.

## Traps & Failed Approaches

- `Cannot access 'gammaCategory' before initialization` — `gammaCategory` was declared at line ~193 but used at ~133 in `analyzeFLB` call. Fixed by extracting early after `rawCategory`.
- Fee fields must be computed BEFORE `calculateEdgeScore` call, not after — otherwise fee penalty/bonus doesn't apply on first pass.
- FLB `bestPrice` must default to `null` (not `yesPrice`) when `bestSide` is null — otherwise fees are computed on a meaningless price.
- At p=0.50, both YES and NO have identical FLB corrections, so `bestSide` is null and `bestEdgeAfterSpread` is 0 — maker sort tests using 50/50 markets get zero rebates. Use off-center prices for meaningful sort tests.
- `computeFeePP` returns pp (e.g., 0.9), NOT percentage points of fee rate. The formula is `effectiveFeeRate * price * 100`, NOT `effectiveFeeRate * 100`.
